# 时间块（右边栏）原型 · 第二轮

> PROTOTYPE，回答「在 DSH 右边栏里怎么把「时间块」App 的手感 1:1 复刻出来」。
> 产物：Open Design 项目 `secretary-prototype` 里的 `time-block-rail.html`；仓库内同名副本 `design/time-block-rail.html`。
> 参考图：Open Design `reference/timeblock-p1.png`（2017 浅色主界面）、`docs/research/assets/timeblocks/appstore-paid-8-dark-expand-all.png`（2018 深色）、用户自己 App 的截图。

## 这一轮改了什么

| 上一轮 | 这一轮 |
| --- | --- |
| 15 分钟格、一行 4 格 | **10 分钟一格、一行 6 格**（`RN = 10`，`PER_HOUR = 6`） |
| 每天一条粗标题条（sticky） | **两天之间只有一条淡虚线**；日期块（月／日／周几／今天）放在左侧日期列里，贴着格阵 |
| 顶部「实录｜计划」分段控件 | **二级模块在标题处切换**：「时间块 ⌄」弹出「实录 / 计划」，一级模块走 ☰ 抽屉 |
| 计划画成每小时顶部细条、并行记录分道 | **不做并行**：一格只有一条记录，赋值即覆盖；计划是独立图层（独立二级视图） |
| 自创的画笔／消除态 | **照 App 的两步制**：点/拖选格子 → 点右侧类别 → 立刻上色；橡皮是唯一删除路径 |

## 对照参考图落下来的细节

- 三列：日期列 46px、小时数字列 22px、格阵（6 格/行、40px/小时），右侧类别列 106px。
- 小时数字只写数字（`0…23`），贴着格阵右侧；日期列里 `11月`（9.5px）／`5`（21px 600）／`周四`（9.5px）／`今天`（accent 色）四行堆叠。
- 跨零点：一条 `1px dashed` 淡虚线 + 下一天的日期块从 0 点开始接着排。
- 色块：2px 内缩、2.5px 圆角、每满一小时切一段（保持「一块一块」的节奏感），标签只在段首出现。
- 类别列：顶部「⌃⌃ 合上所有内容」（收起后只剩一个色点），底部「更多事件类别」。
- 底部状态栏只在有选区时出现：`选择了 30 分钟` + 右端红色橡皮；选中已有色块时换成「类别 · 备注」+「备注」按钮。
- 现在时刻：一条 1px 静线 + 小点（App 本身很弱，这里也没做强）。
- 明暗两套；类目色沿用真实数据（工作 #477bc7、生活 #317b68…）。

## 已驱动验证（Chromium）

- 拖选 14:00 起 3 格 → 底栏「选择了 30 分钟」→ 点「阅读」→ 记录落到 14:00–14:30，底栏收起，Toast「已记 阅读」。
- 点已有色块 → 整条选中（底栏显示类别 + 备注入口）；拖选时改为区间选择。
- 橡皮删除选区；撤销恢复。
- 「时间块 ⌄」弹出二级菜单 → 切「计划」→ 标题变成「时间块 · 计划」，画布换图层并滚到当前时刻。
- ☰ 打开一级抽屉；Esc 关闭。
- 明暗切换、无 page error、420px 无横向溢出。

## 没做

深度时间、事项、标签、目标、统计都只有入口或占位；编辑浮层（起止 ±10 分钟、备注、改类别、删除）已接上，但没做「拖动块改时间」。

## 第三轮修正（两屏页面）

- **每格独立成块**：不再把连续格子合成一个大块。每个 10 分钟格都是一块独立的长方形，格间留 1.5px 缝，这就是「时间块」的颗粒感；文字只写在段首格或有备注的格上。
- **默认宽**：产品栏 660px（原 420px），格阵 6 列 × 约 73px，格子呈横向长方形。
- **选中态**：浅蓝底 + 白色 ✓，和 App 一致；选中时不再显示块上的文字。
- **页面结构**：改成「左产品 / 右会话」两屏，DSH 左侧会话栏收起，顶部一条 app bar（品牌 + workspace 路径）。会话列在原型里是假的（真实实现要用宿主 `conversation.content` factory 嵌入）。

## 选中/取消（第五轮修正）

| 动作 | 结果 |
| --- | --- |
| 单击一个未选中的格 | **追加**一个选中（可以连点累积） |
| 单击一个已选中的格 | **只取消这一格** |
| 按住拖过一片 | **取消之前所有选中**，只留拖过的这一段 |
| 底栏「不选」/ Esc / 点画布外 | 清空 |

选中态**不改格子颜色**：连续段的格子外面加 2px 白描边，格内一个小勾。所以一个块不会因为一半被选中而出现两种颜色，也不会和 12 个标签的颜色撞。底栏：`选择了 N 分钟` ＋「不选」＋「橡皮」。

## 一屏一天（第六轮修正）

- 行高动态计算：`ROW_H = 可视高度 / 24`，夹在 22px（下限）与 64px（上限）之间；resize 去抖 120ms 后重算并重建画布。
- 进入/切图层时把「今天」的 0:00 对齐到画布顶部 —— 24 行正好铺满一屏，当前时刻线在屏内。
- 画布最小高度 = 24 × 22px = 528px（`--min-day`）；窗口更矮时不再压行高，改为画布内部滚动。
- 实测：视口 1200 → 46.3px/行；900 → 33.8；760 → 28；640 → 23；520 → 固定 22px + 滚动。每档 `一天高度 == 画布可视高度`。
- DSH 侧：Web 外壳 `AppFrame` 只有 `min-height: 0`，桌面端主窗口在 `app.asar` 里没找到最小尺寸设置（只有欢迎页/登录页的固定 720×760 等）。所以窗口可被拉得很矮，最小高度由我们自己兜。

## 只画整格（第七轮修正）

原因：数据里的起止时间是任意分钟（06:55、07:25…），而画布是 10 分钟一格，边界就会切出「半个块」，一格还可能被两条记录分成两种颜色。

现在：所有记录对齐到 10 分钟格（起点向下取整、终点向上取整），渲染器只按整格画，几何上不存在分数宽度。审计脚本检查每个块宽度 == 一格宽度，例外数 0。存储仍保留真实时间，画布只负责把它外扩到整格显示。

## 第八轮：回到窄栏 + 移动端交互

- **产品栏固定窄栏** 560px（可拖 460–620）。时间块是手机 UI，拉宽只会难看；不再居中漂浮。
- **交互恢复**：一级模块＝左上 ☰ 抽屉；二级＝标题 `时间块 ⌄`（实录/计划）。顶部不再有任何额外切换行。
- **去框线**：画布、类别列、状态栏之间只留极淡分隔，不做卡片和圆角外框。
- **事项改成移动端形态**（OmniFocus iOS：透视条 + 单列大纲）：顶部透视 chips（今天/收件箱/项目/预测/已标注/回顾 + 计数），下面是单列大纲，行内是状态圈 + 标题 + 右侧日期，无行分隔线，选中是整行底色。

## 待你确认

1. **日期位置**：你提到「日期是在右边」，但两张参考图里日期块都在左侧日期列。这一版按参考图放在左上、紧贴格阵。如果你说的是「放到右边」，我把它挪到格阵右侧。
2. **并行**：现在一格只允许一条记录，赋值即覆盖。以后要并行的话，是「同格上下分栏」还是「第二条记录用斜线/半透明」？

## 第九轮：原型落进真实产品（右栏 tab）

原型定稿后不再改视觉，开始把它做成真的：

- **载体**：`packages/panel` 从「全局主面板 + 左侧栏入口」改成**右栏 tab**（`ctx.sidebarRightTabs.register({ id, kind: 'secretary', priority: 'builtin', title: '小秘书' })` + `sidebar.right.pane.tab` body）。聊天留在中栏，产品在右栏窄列，和原型布局一致；入口是右栏 guide 里的「小秘书」胶囊。
- **砍掉的东西**（按原型）：粒度切换 10/15/30、开始/停止计时、计划模板 apply/undo、并行记录分栏、右键菜单式编辑、标签管理器。这些 Service 能力保留给 agent，UI 不再暴露。
- **时间块画布**：`TimeCanvas` 用 10 分钟格铺 7 天，`rowH = clamp(22, 64, 可视高度 / 24)`，一格一天正好一屏；方块无圆角、每格带字；选区描边按小时断开，✓ 逐格；`不选`/`Esc`/点空白清空，`橡皮`/`Delete` 擦除；底栏高度常驻，避免选区出现时画布重排把指针下的格子挪走（原型里踩过）。
- **上色语义**：`time.paint` 在 Host 侧把选中的 run 从所有重叠记录里切出来（跨午夜也按绝对时间算），再落新块，最后合并同色相邻块。撤销＝`time.replace` 整日回写快照，绕开 ID 重映射。
- **深度时间**：数据层从单一 base 周模板改成按周（`DeepWeek = { weekStart, source: 'own' | 'inherited' | 'seed', cells }`），没画过的周继承最近更早的周，写入只落本周；UI 是 7×24 小时格 + 周切换 + 矩形拖选 + 三档画笔。
- **主题**：全部走 `--dsw-alias-*`，不再自带调色板（原型里的 dark/light 变量只用于自证）。
- **验收**：`packages/secretary/tests/tracer.mjs`（50 条，含 Host route 同源与按周隔离）＋ `packages/secretary/tests/browser.mjs`（6 条真 Chromium：骨架、拖选上色/不选/Delete/撤销/reload、备注浮层、实录与计划互不影响、深度时间画一周+继承+只改本周+重启存续、事项捕获、明暗主题无页面错误）。
- 截图：`design/product-time-dark.png`、`design/product-select.png`、`design/product-deep.png`。

## 第十轮：日期 / 周切换（先在原型里定）

反馈：标题下面单独一行「‹ 11月2日 – 11月8日 ›」看着像控件却不是控件；原生 `input[type=date]` 的弹层不受主题控制，很丑。所以先在原型里做：

- **标题栏右侧统一成一个控件**：`‹  11月4日 周三  ›  今天`（时间块）／`‹  11月2日 – 11月8日  ›  本周`（深度时间）。左右箭头步进一天／一周，中间是可点的标签，最右是回到今天／本周。
- **自绘日历弹层**：月网格（周一起始）、上下月箭头、今天高亮、选中态；深度时间模式下整周高亮（两端圆角），底部显示该周范围；点任意一天即落到那一天／那一周。Esc 与点外部关闭。
- 原型里同时把「时间块」的日期列表改成可跳转：选天会把画布重铺到该天并滚过去（真机是连续列表，见第十一轮）。
- 截图：`design/picker-day-dark.png`、`design/picker-week-dark.png`、`picker-week-light.png`。

## 第十一轮：切换定稿与两条记入领域文档的决定

- **时间块按天步进、深度时间按周步进**（外观同一套控件，步进对齐各自阅读单位）。
- **弹层允许压住类别列**：临时态，选完即关；不做居中模态。
- **弹层不显示 ISO 周数**：周标签继续用 `11月2日 – 11月8日`。
- **实录 / 计划 共用同一个日期锚点**：切图层停在同一天，才谈得上对比计划与实际。
- **键盘**：`←` `→` 步进一个阅读单位，`PgUp` `PgDn` 步进一周，输入框内不拦截。
- 领域文档同步：`docs/glossary.md` 的「时间格粒度」改为**固定 10 分钟**；「并行时间」保留定义但标注**画布当前一格一条、并行呈现方式未定**（用户确认并行以后再做）。
