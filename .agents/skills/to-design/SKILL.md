本技能把当前对话（拷问结论）与代码库理解综合进需求 Issue。不重新访谈，只综合已谈清楚的内容。

先读[工单约定](../../../docs/agents/issue-tracker.md)。

## 过程

1. 读需求 Issue 原文与评论；需要时查看相关设计契约与现有实现，用项目领域词汇书写，遵守涉及范围的 ADR。
2. **需求（含设计）**：把设计要求补充进需求，检查原有需求与当前结论不一致的地方并修正；范围外（明确不做的）也写进需求。交互要求按用户故事组织，每条故事独立可测；验收场景用「**Given** 初始状态，**When** 用户操作，**Then** 界面预期」写，场景同时是设计确认的单位。
3. **评论**：补充开发和技术部分——涉及的模块与接口、技术澄清、架构决定、数据形状。不写具体文件路径和代码片段，它们很快过期；原型产生的、比文字更准确表达决定的状态机 / reducer / 类型形状可以内联并注明来自原型，只保留承载决定的部分。
4. 写后回读，按工单约定更新状态。

不新建票。
