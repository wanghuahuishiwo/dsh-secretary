# 阶段边界

**阶段**是会话内的一块工作：grilling、实现、QA。定义故意模糊：当你觉得「好，这块做完了」的时候，一个阶段就结束了。

**阶段边界**是两个阶段之间的空隙，而这个决定只属于那里。阶段中间没有决定可做：继续，或者把剩下的工作拆给子代理。在阶段中间 compact 会让 agent 丢掉线索。

## 五个选项

| 选项 | 做什么 |
| --- | --- |
| **继续** | 留在会话里。完全无上下文切换。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 写一个可携带的 markdown 文件，在任何地方用它给一个会话播种。 |
| **子代理** | 把任务送到它自己的上下文窗口，拿回一份报告。 |
| **`/compact`** | 压缩这段上下文，用摘要给一个新会话播种。 |

## 决策树

在边界上从上往下走。第一个**是**获胜。

**1. 你能在这个会话里继续吗？** 两件事让答案是「是」：下一阶段需要这一阶段作为**一手资料**，或者你剩下的 smart zone（约 150k tokens）够下一阶段放得下。Grilling → 实现是标准的「是」：实现想要的是推理的原文，而不是它的摘要。继续不花成本也不丢东西，所以在任何其他选项之前先排除它。

**2. 这段上下文对接下来无关吗？** 这个会话里的一切（探索、决定、死路）都可以丢吗？如果是，**`/clear`**。它是棋盘上最便宜的走法：不花时间，还回整个窗口。`/clear` 也不是终点：旧会话仍然可以恢复。

做错的代价是单向的。清掉一段*相关*的上下文，你就会丢掉你构建的东西背后的**为什么**，而读多少 diff 都拿不回来。

**3. 你需要交接吗？** `/handoff` 很窄。只有当你：

- 换到**新 harness**（Claude → Codex），
- 搬到**新目录**或 repo，
- 把工作交给**同事**，
- 或者在**阶段中间**分叉出你发现的一个支线任务、又不带偏你正在做的事

时才需要它。这份清单就是全部条款。`/handoff` 买到的是**可携带性**：一个能走的文件。如果没有任何东西要走，你就不需要它。

**4. 任务能 AFK 做吗？** 它的范围是否紧到可以在你离开键盘、没有 steering 的情况下运行？那就把它交给**子代理**，这个会话不动。自动审查是标准情况：agent 读 diff 并报告，它做的时候不需要你。

**5. 否则，`/compact`。** 上下文相关、同一个 harness、同一个目录，而你又需要留在环里：这就是树落地的地方，而且它经常落在这里。给它一条指令（`/compact 我们接下来要 QA 这块区域`），好让摘要保住下一阶段需要的东西。

`/compact` 是**默认，不是第一反应**。它在最底部，因为上面四个问题都更便宜或更精确。当人们从这里开始时，失败模式是一个新会话，对某个被摘要压平的决定自信地做错。

## 一手与二手资料

除**继续**之外的每个动作，都把一份**一手资料**变成一份**二手资料**：发生过的会话，被它的摘要替代。交换的形状总是一样的：

| 来源 | 信息 | 噪音 | 腾挪空间 |
| --- | --- | --- | --- |
| 一手（继续） | 完整 | 多 | 小 |
| 二手（`/compact`、`/handoff`） | 有损 | 少 | 大 |

这就是为什么问题 1 放在最前面。只有当留下来的成本大于它省下的东西时，你才付这份有损。

## 这些是判断题

这些问题不是客观的：每一个里面都有品味，同一道边界可以在两天里走成两个样。价值在于**按顺序**问它们，在边界上问，而不是在工作中间。
