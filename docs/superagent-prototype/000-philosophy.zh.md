# 000 哲学（Philosophy）

> 中文译本，仅助读；英文原文为权威版本：见原型仓库 `dsh-superagent-prototype/docs/000-philosophy.md`（翻译于 2026-11-17）。

dsh-superagent 是一个框架，也是一种与 agent 协作的工作方式。它的核心原则：

**尽可能少地消耗人的注意力，尽可能多地给出价值。**

项目的每个部分都以它消耗的注意力来评判。一条消息、一个通知、一个问题、一个设置、一个面板元素、一段文档，各自都在花费某个人的注意力，各自给出的价值必须超过这份花费，否则就被移除。

## 由此对 agent 的要求

- **它只在被请求时、或被写下的规则允许时行动。**一个请求只有直接指向 agent、且来自团队允许的人时才算数：在允许名单（allowed list）上的人，或团队开放了请求的会话中的任何人。没人请求过的工作，需要一条团队写下的规则才可做，并且初始只能以"只记录 agent 本会做什么"的模式运行。
- **它只在有人必须行动、或有人能用上结果时才说话。**收到请求确认一次，说明它将做什么。工作期间保持安静。结果就绪、需要人做决定、或它做不下去时，它再次发言。消息简短，发到请求所在的那个会话里。
- **它一次只问一个具体的问题**，用结构化的形式，让问题能到达人，而不是埋在一份长报告里。
- **它按影响决定停在哪，不按投入的努力。**一个局部改动推进到可评审的结果为止；需要设计决策的改动，带着一个清晰的问题停下来。
- **它诚实汇报。**草稿标记为未完成，失败如实报失败，绝不为了不问人而绕过限制。

## 由此对设计的要求

- **概念要少。**设计只包含它的领域概念（如 Source 来源）及其具体实现（如 GitHub 和 Feishu）。一个业务需要，变成其中某个概念的属性，或变成 agent 遵循的一段 prompt 文本。设计不为它新增概念。
- **设置要少。**当一个值适合几乎每个团队时，用默认值替代设置。团队能用语言描述的行为，是 prompt 文本，不是设置项。
- **面板只显示需要人看的东西。**它优先列出等待人处理的事项。健康的状态不占空间。
- **文档按顺序读。**每篇编号文档只建立在它之前的文档之上，读者永远不会需要尚未引入的概念。

## 责任

agent 以你团队每天都能看到的账号发评论、开 pull request、给人发消息。它发出的每条消息都在消耗你同事的注意力，而你要为它负责。agent 能做的越多，运营者对团队欠下的谨慎就越多：

- **从小处开始。**以一个短的允许名单起步，主动型工作初始只记录不执行。等"agent 本会做的事"看起来正确之后，再逐步放宽两者。
- **为更少的噪声调优。**agent 太吵时，把它的 prompt 改得更短更严，或暂停它。不要用更多的消息去解释噪声。
- **不用它生产量。**批量 pull request、群发消息和凑数的工作，给团队的消耗多于贡献。
- **为它说的话负责。**读它以你的名义发出的内容，错了就在 prompt 里纠正。

目标是在正确的时刻提供正确的帮助，其余时刻什么都不做。
