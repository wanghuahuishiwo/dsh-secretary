# 005 面板（Panel）

在 DeepSeek Harness Web 侧栏中打开 **Superagent**，即可监管 agent。面板优先呈现需要人处理的工作，然后是系统健康状况与历史。本文以 [000 哲学](000-philosophy.zh.md) 至 [004 提示词](004-prompts.zh.md) 为基础。

## 三个问题

打开面板会按顺序回答三个问题：

1. 现在有需要我处理的事吗？
2. 系统健康吗？它在做正确的事吗？
3. 某项工作从触发（Trigger）经评估（Eval）到工单（Ticket）的历史是怎样的？

## 标签页

标签页跟随工作流：**概览**、**来源**（Source）、**触发**、**评估**、**执行**、**设置**。在仓库与账号设置成功之前，概览会显示缺少什么，并链接到相关设置。

| 标签页 | 显示内容 |
| --- | --- |
| 概览 | 需要处理的工单、系统问题、过去 24 小时的活动计数，以及执行器（Executor）负载。每个区块都链接到对应详情页 |
| 来源 | 来源状态、设置问题和非零计数。筛选后的触发与被丢弃的消息，覆盖与概览相同的 24 小时窗口 |
| 触发 | 按“已订阅”“评估中”“24 小时内的新触发”或“全部线程”筛选的线程（Thread）。每个线程按最新优先展示其触发、决定和订阅 |
| 评估 | 决定（Decision）及其原因和匹配的规则 |
| 执行 | 执行器状态、暂停处理，以及按“未结”“待处理”“工作中”“等待触发”或“已结束”筛选的工单。工单详情展示动作、授权、等待中的输入（Input）、订阅和派工（Assignment） |
| 设置 | 来源、评估、执行、提示词和部署。每组都附带其保存历史 |

### 查看单条记录

被丢弃的消息会链接到它的工单；若它没有工单，则链接到它的线程。来源页会说明是其会话消失了，还是来源已不再监听它。

仍由执行器负责的人工跟进会标记为 **已投递到工单**（Delivered to Ticket），不经过评估。线程还会显示交还原因和只提供上下文的订阅。**重新评估**（Evaluate again）可以把这条跟进送去评估，也可以重试一个没有有效判定的触发：被其来源过滤掉的、评估不可用的，或者已投递但既没有“不停止”的决定、也没有执行器确认的消息。

工单详情会展示原始触发、决定与原因、范围（Scope）和策略版本。派工和次要细节折叠在即时动作之下。**重试**（Retry）可用于投递失败的输入，或用于报告被阻塞、失败后正在等人处理的工单。已结束的工单会展示结果，例如 **拉取请求已合并** 或 **被人工停止**。

## 设置分组

- **来源：** 每个来源一张卡片，带开关、字段和已验证的账号信息。GitHub 还提供针对新 Issue、拉取请求、评论和默认分支 CI 的“全部接收”开关。轮询与读取限制位于“高级”下。
- **评估：** 策略版本（Policy version）与规则，随后是 **按来源**（On each Source）和评估设置。每个来源标签页包含其允许列表、成员同步、准入（Gate）表和机器人列表。同步会在启动时运行，也会在 **立即同步**（Sync now）时运行。准入表区分接收范围、发送者成员资格，以及消息是否针对 agent。评估设置用于选择接受模式、超时和研判（Assessment）模型。
- **执行：** 工作模型、并发数、目录根、准备命令和被禁用的命令。点击一个可用变量会把它插入准备命令。
- **提示词：** **编辑** 可修改团队段落、内置部分和技能。**完整提示词** 展示装配后的文本，并与已保存的文本或默认内容对比。**历史** 列出各版本。被编辑过的内置部分会标记为已更改，并可重置；模板会列出自己必需的占位符。

  升级若改动了某个被覆盖的默认内容，就会把该部分标记为 **默认内容已更新**（Default updated）。面板在团队文本上方对比新旧默认内容。若没有记录旧默认内容，则改为将团队文本与新默认内容对比。选择 **保留我的文本**（Keep my text）或 **使用新的默认内容**（Use the new default）。已移除部分的覆盖项列在标签栏下方，并在下次保存时丢弃。
- **部署：** 启动问题（带 **重新检查**（Check again））、状态目录和机器限制。已保存的限制无需重启即可生效。DeepSeek Harness 插件管理器会展示同一个页面。

## 搜索

页头搜索按文本、id、飞书消息 id 或已存储的链接（例如 GitHub 评论 URL）查找触发。若某条飞书链接在原消息中缺失，则只有在当前进程生命周期内宿主读取过它之后，它才变得可搜索。

搜索还可以按引用（例如 `#12` 或 GitHub URL）查找线程，并按标题或匹配的线程查找工单。

## 原则

1. **聚焦真正重要的事。** 每个元素都要回答三个问题之一，否则就删掉。只有当数字会改变监管者的做法时才显示数字。
2. **定义精确。** 类别都有可核查的定义，彼此互斥且覆盖所有情况，工单阶段也是如此。标签说明这一行在等谁、需要什么，而不是内部状态码。
3. **每个概念只有一个位置。** 来源状态归来源页；线程与触发归触发页；决定归评估页；工单归执行页。设置按其所配置的概念分组。概览汇总这些页面并链接过去，而不是变成又一个详情视图。
4. **使用领域结构。** 面板使用领域术语。内部标识符只出现在折叠的详情中，能解析出名称时用名称替代标识符。
5. **诚实的状态。** 计数等于它所链接列表的长度，且任何状态都不得与另一项事实矛盾。
6. **默认安静。** 健康状态不占额外空间。问题必须可采取行动；一次性的网络错误不算。需要人处理的行直接给出对应动作。页面说明控制在一句话，更多细节放进 (?) 提示框。破坏性操作需要确认。
7. **控件一致。** 使用 DeepSeek Harness 的设计令牌和控件行为。同样的信息在面板各处应当看起来一致。每个设置区块只有一个保存栏，仅在存在改动、正在保存或保存失败时可见。
