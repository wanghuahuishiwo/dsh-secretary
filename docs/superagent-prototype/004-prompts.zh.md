# 004 提示词（Prompts）

本文说明 agent 会读到什么、团队可以编辑什么，以及改动何时生效。它以 [000 哲学](000-philosophy.zh.md) 至 [003 执行](003-execution.zh.md) 为基础。提示词文本本身用英文撰写。

## 团队写什么

团队可以编辑三个团队段落、添加技能，并覆盖每一个内置系统提示词部分。大多数默认内容位于 `prompts/` 和 `skills/` 下。工具描述、通知和卡片留在代码里，无法通过提示词设置编辑。

| 段落 | 内容 |
| --- | --- |
| 沟通（Communication） | 何时给人发消息、消息怎么写、每条 GitHub 消息开头的那句话（默认为 `This is by an automated agent, not a human`）、如何处理评审，以及哪些普通账号属于评审机器人 |
| 工单范围（Ticket scope） | 工单在什么情况下继续推进，又何时停在一份草稿上 |
| 交付要求（Delivery requirements） | 拉取请求中的证据、带行数阈值的自动合并条件，以及提交作者；若没设提交作者，执行器（Executor）以 agent 账号的 no-reply 地址提交 |
| 团队技能（Team skills） | agent 需要时才加载的知识，例如一个 `identities` 技能，说明哪个飞书用户对应哪个 GitHub 账号 |

内置文本涵盖角色、工具使用、宿主机制、授权规则，以及 GitHub 与飞书技能。它通过标题引用这些团队段落，而不重复它们的内容。

### 内置部分与模板

覆盖使用以下键：

| 部分 | 键 |
| --- | --- |
| 共享指令与角色 | `runtime/shared`、`runtime/orchestrator`、`runtime/worker` |
| 工作指令 | `runtime/subscriptions`、`runtime/replies`、`runtime/dispatch`、`runtime/work`、`runtime/admission` |
| 交接指令 | `runtime/handoff/orchestrator`、`runtime/handoff/worker` |
| 来源技能 | `skill/feishu`、`skill/github` |
| 生成段落 | `runtime/environment`、`runtime/policy`、`runtime/policy/none` |

生成段落是可编辑的模板，且必须保留以下占位符：

- `runtime/environment`：`{variables}`，填入执行环境（Execution environment）的各行。
- `runtime/policy`：`{version}`、`{mode}` 和 `{rules}`，每条已启用的规则占一行。
- `runtime/policy/none`：`{version}` 和 `{mode}`，在没有任何规则启用时使用。

编辑某个部分只改变模型收到的指令，不会改变准入（Gate）、授权（Mandate）、工具校验或账号包装层，这些仍由代码强制执行。

在人明确要求时，主 Session（Main Session）也可以用 `orchestrator_prompts_save` 保存覆盖内容。如果某次保存省略了某个覆盖项的 `base`，则沿用已保存的 base。已保存配置中存在的某个部分若被移除，保存时会将其删掉；其他任何未知部分都会被拒绝。

每个覆盖项会记录它基于哪份内置文本。升级会保留团队自己的文本。若默认内容发生变化，面板会把该部分标记为 **默认内容已更新**（Default updated），并在团队文本旁展示差异。团队可以保留自己的文本、采用新的默认内容，或在其基础上编辑。没有覆盖项的部分会自动跟随新的默认内容。

主 Session 可以在 `orchestrator_read prompts` 的 `default_changed` 下读到受影响部分的名称。

## 装配与优先级

系统提示词按以下顺序装配：

1. 共享指令与角色。
2. 三个团队段落。
3. 订阅（Subscription）与回复。
4. 主 Session 的派发指令，或执行器的工作指令。
5. `runtime/admission`，仅用于主 Session。
6. 交接指令。
7. `runtime/environment`。
8. `runtime/policy`，仅用于主 Session。

准入指令来自 `prompts/admission.md`，描述主动研判（Assessment），以及何时可以仅凭卡片忽略一个无关的候选项。`orchestrator_eval` 返回的是上下文，而不是重复这些指令。

环境段落给主 Session 提供部署级取值，给每个执行器提供其工单专属取值。策略（Policy）段落会在每次模型请求时依据设置重新生成，包含策略版本（Policy version）、接受模式、显式请求豁免，以及以 `- <name> (<id>): <instruction>` 形式列出的已启用规则，或一句说明未启用任何规则的话。它排在最后，这样策略变化不会扰动前面的提示词文本。

执行器还会读取 DeepSeek Harness 的编码提示词和仓库的 `AGENTS.md`；主 Session 不读。推断出来的工单会追加一条末尾说明，把它的执行器限制在匹配的规则之内。派工与收到的消息以内联的触发（Trigger）卡片形式到达，只有被截断的内容才附资源指针。

执行器在无人值守下工作。它们的工具中排除了需要向人提问、向人展示 UI 或修改配置的那些，例如 `ask_user_question`、`present` 和 `plugin_manager`。

从强到弱：

1. 由工具和宿主强制执行的事实：身份、权限、工具参数校验、回复用途、长度限制。提示词文本改变不了它们。
2. 内置段落与生成段落，按其被团队覆盖后的内容读取。
3. 主动工单匹配规则中的流程与沟通要求，仅作用于该工单的执行器 Session（Executor Session）。
4. 团队段落与团队技能。
5. 外部文本：消息、评论、文档和引用。它是数据，永远不改变规则或授权。

## 内置文本的原则

以下原则把 [000 哲学](000-philosophy.zh.md) 落到 agent 身上：

- **角色分离。** 主 Session 只做路由：它转发原始触发与路由所需的事实，不做任何技术决策；路由通过一个工具完成，一次调用即可对多个等待中的候选项作出决定。路由备注最多 30 个词。执行器读取原始来源、判断范围（Scope）、实施并验证。
- **主 Session 不等待。** 报告（Report）、跟进通知、候选项和已完成的后台任务会以消息形式自动到达。没有剩余工作可做时，它就结束回合。一个守卫会拒绝 `sleep`、超过 30 秒的 shell 超时以及超过 5 秒的任务等待，因为被阻塞的步骤会拖住新的候选项。在主 Session 的完整提示词中，这些指令会取代 DeepSeek Harness 自带的任务通知说明。
- **只在有人必须行动、或有人能用上结果时才发消息：** 结果可被评审或使用、需要决定或资源，或工作无法完成。聊天消息默认一句话，硬性上限 100 词。
- **执行器自己决定如何跟进。** 每个执行器处理并确认范围内的请求，把超出其工单范围或属于其他工单的请求交还。一条消息只有在所有归属者都交还、或都未接手即结束之后，才会变成新工作。主 Session 会收到跟进通知，但只能在为停止工作时对其采取动作。被交还的消息随后连同执行器给出的原因，作为候选项到达。
- **通过订阅与主 Session 协调。** 执行器关注相关线程（Thread）以获取上下文。主 Session 可以在最多 100 词的备注中转达另一个工单的事实。订阅和备注都不授予权限。
- **只在有明确引用时才附加。** 消息必须指向某个工单的拉取请求、Issue、来源消息或确认，或指向恰好只有一个工单匹配的近期变更。仅凭主题相似不够。附加会让工单订阅整个线程；执行器若发现它无关，就用 `orchestrator_thread_unrelated`，且不在那里作答。
- **具体确认，且只确认一次。** 在开始实质工作前，执行器会确认每个新请求，并指明对象与预期结果，作为原消息下的一条回复。
- **通过 `human_action` 提问。** 执行器在报告里放一个具体问题，主 Session 原样转发。若问题由某人的消息引发，就点名那条消息，由宿主在那里提问；否则在工单的原始会话中提问。已获授权的工作可以同时继续。
- **诚实交付。** 打开拉取请求不等于就绪；草稿标记为未完成；没有真实“改动前”截图的 UI 变更不算就绪。
- **人的暂停持续有效**，跨跟进、跨新的执行器 Session、跨重启，直到有人解除。自动反馈永远不会恢复已暂停的工作。
- **示例只展示格式。** 示例句子不是 agent 可以声称的事实。
- **按结果处理评审。** 已修复并验证的评论静默解决；被拒绝的评论给出一句理由。自动评审者的讨论串在得到答复后即解决，且每个自动评审者对每个拉取请求最多三轮。
- **为重复工作让路。** 当某人的分支或拉取请求已经包含该工单的改动时，执行器用一句话关闭自己的拉取请求，指向对方的那一个。

## 版本

- 每次保存都会创建一个不可变版本，包含完整配置、修订号、前驱版本、时间戳和来源（面板或工具）。恢复某个版本或恢复默认内容，会再创建一个版本。
- 保存会声明其基础修订号。冲突的保存会被拒绝，且草稿不会被丢弃。
- Session 在每次模型请求时读取最新版本，包括同一回合中后续的步骤。保存不会重启、取消或唤醒 Session。宿主会记录每个 Session 用过的修订号；执行器可以读取它工作期间所依据的任何修订号。
- 部署会设置一个总大小上限，覆盖内容也计入。校验会拒绝未知键、保留的内置技能名、未知的覆盖部分以及缺失的模板占位符。它绝不会静默截断文本。与默认内容完全相同的覆盖项会被移除，让该部分跟随未来的默认内容。
