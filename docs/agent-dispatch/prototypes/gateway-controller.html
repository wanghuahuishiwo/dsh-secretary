原型 · 本机 Gateway 控制器 （可丢弃，回答一张决策票）

要回答的问题：DSH 的设置 UI 与命令行如何管理一个「独立于 DSH、桌面退出后还活着」的本机 Gateway 进程—— 启动/停止/重启/状态怎么表达；DSH 关掉再打开，怎样认出并重新接管同一个实例；启动中、启动失败、异常退出如何呈现； 最少要持久化什么（实例记录、PID、日志位置）。
原型假设（待你推翻）：① 不做常驻管理器——控制器是一段无状态的共享库，UI 插件和命令行都调它，真相 = 探测操作系统 + 一份实例记录文件； ② 用 nats-server 官方能力做身份与健康探测：启动时传 -n <实例ID> 作为 server name，经监控端口 /varz 读回核对（防 PID 复用误判）； ③ 控制器只在桌面进程里 spawn 一次并以 detached 方式脱手，之后不再持有子进程句柄。

怎么玩：左边是控制器看到并显示给用户的状态，右边是模拟的真实世界（操作系统里发生了什么）。先用下方「向导」走一遍刁钻场景，再用「自由操作」乱按。 看到不对劲的地方——"这不应该允许吧""我以为是另一种"——就是这张票要的答案。
已结单（#87）后的勘误：本原型定案时有两处被推翻——① 每次启动一个新 instanceId 作 server name 的"身份"设计已撤回，Gateway 没有身份概念，认进程靠 pid 活着 + /varz 的端口与 jetstream.config.store_dir 与本机配置一致；② 就绪探针不能用"/varz 可达"（监控口早于客户端端口启动），改用官方 GET /healthz?js-enabled-only=true。另："控制器"一词在定案中改称"Gateway 管理"，其入口是"底座控制台"。其余状态机（启动中／运行中／停止中／启动失败／异常退出／记录失效／无法确认／未托管）按原型定案。
