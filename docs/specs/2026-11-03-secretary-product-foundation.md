# 小秘书一期产品基线：GTD、Time 与 Tag

> 状态：`ready-for-agent`，已发布到 [GitHub Issue #1](https://github.com/wanghuahuishiwo/dsh-secretary/issues/1)。
> 日期：2026-11-03。
> 领域权威：`docs/product-architecture.md`、`docs/data-model.md`、`docs/glossary.md`；交互基准为 OpenDesign `secretary-prototype` 的 Version 9。

## 问题陈述

用户需要一个真正可用的私人 Secretary Agent，而不是彼此割裂的事项表单、计时器和对话窗口：

- GTD 管理尚未闭环的承诺，OmniFocus 的核心逻辑不需要重新发明。
- 睡觉、吃饭、洗漱、通勤等不占 GTD，但计划与实录必须覆盖全部生活时间。
- 计划和实录都需要精确到日期；周模板只能作为复用工具，否则无法处理小长假。
- 时间记录需要像优秀直接操作应用一样高效，不能依赖新增表单、逐格编辑或只能删除当前标签的残缺交互。
- 时间标签与 GTD 情境需要共享独立 Tag 能力，同时保持不同用途和清晰继承规则。
- Agent 与手动 UI 必须调用同一批原子能力，不能让 Agent 另建一套事实或把使用策略写进领域模块。

当前实现仍停留在旧的“Action 关联 planned／actual TimeBlock”模型，且实验面板不是已确认的产品结构，需要按新基线重构。

## 解决方案

交付一个安装在 DSH 中的小秘书产品：

1. **GTD** 按 OmniFocus 的核心产品逻辑管理 Inbox、Project、Action 及其可用性。
2. **Time** 包含日期计划、日期实录和深度时间三个子模块，复用 A 方案的右侧时间标签架和直接操作画布。
3. **计划模板** 是计划页中的独立功能，按星期维护并显式应用到日期，不与日期计划持续绑定。
4. **Tag** 是独立一级模块，用统一字段与管理交互维护 `time`／`context` 两棵树。
5. **Agent** 不设置独立 UI，通过原子工具操作同一批领域事实；具体使用策略以后由 Skill 组合。
6. **Goal** 保留为重要一级模块，但本期不实现；统计、预算和对账另行专题设计。

## 用户故事

### GTD 与 Tag 关联

1. 作为用户，我希望原样捕获尚未闭环的承诺，从而避免把已经立即完成的两分钟事项、参考资料或睡觉吃饭等日常活动塞进 GTD。
2. 作为用户，我希望在澄清时建立 Project 与 Next Action，并用 Defer、Planned、Due、Estimated Duration 表达不同日期语义，从而避免把柔性意图误当硬截止时间。
3. 作为用户，我希望顺序项目、并行项目、单一行动清单、Action Group 和可用性遵循 OmniFocus 规则，从而不需要学习另一套 GTD 模型。
4. 作为用户，我希望 GTD 的 Inbox、Next Actions、Forecast、Review 与 Repeat 等核心交互参考 OmniFocus，从而减少迁移和认知成本。
5. 作为用户，我希望每个 Project 必须有一个时间标签，其所有后代 Action 自动继承，从而不用逐项维护时间分类。
6. 作为用户，我希望 Action 自己设置的 Tags 与 Project、父 Action 的所有 Tags 累加，而不是覆盖继承；无父层级的独立 Action 自己设置时间标签，从而保证每个 Action 都有有效时间标签。
7. 作为用户，我希望时间块不直接关联 GTD，备注可以提及 Project／Action，从而让睡觉、娱乐和并行生活时间保持合法且简单。

### 日期计划与计划模板

8. 作为用户，我希望计划和实录都按具体日期浏览，从而可以准确安排普通工作日、周末和小长假。
9. 作为用户，我希望点击日期文字打开月历、跨月选择任意日期，同时保留逐日箭头，从而不用一天一天翻页。
10. 作为用户，我希望日期栏和月历都提供“今天”，并在月历中高亮真实当天，从而随时快速返回。
11. 作为用户，我希望独立维护周一到周日的计划模板，并明确应用到当前日期，从而复用常规作息。
12. 作为用户，我希望模板应用后可以单独调整该日计划，且不回写模板、不修改实录，从而兼顾复用和例外。

### 时间画布与并行

13. 作为用户，我希望一小时一行、默认每小时六个独立 10 分钟小方块，并可切换 15／30 分钟，从而匹配自己的记录习惯；切换粒度不改变已有时间事实。
14. 作为用户，我希望右侧始终可见时间标签树，父标签和子标签都能直接使用，从而以最少动作完成标记。
15. 作为用户，我希望选中标签后，点击不含该标签的格子就添加为并行，点击已含该标签的格子就消除该标签，从而在同一手势中完成添加和取消。
16. 作为用户，我希望双击右侧已选标签进入消除态，此时可点击或拖刷消除任意记录，单击任意标签退出，从而不必为删除其他标签反复切换画笔。
17. 作为用户，我希望一次消除拖刷只处理起手标签，避免剩余并行块改变位置后被连锁误删。
18. 作为用户，我希望 Shift + 点击才打开备注、标签修改或删除编辑，普通点击不弹编辑器，从而让直接操作保持干净。
19. 作为用户，我希望同一格中有多少条并行就多少等分，三条三等分、四条四等分且不增加小时行数，从而表达真实并行而不是制造虚假的上限。
20. 作为用户，我希望记录跨小时时填充对应格子、标题只在首个格显示，小时行高保持 48px，时间块使用与深度时间一致的实心标签色、4px 圆角和细间距，从而保持紧凑一致。
21. 作为用户，我希望撤销添加、消除、编辑和模板应用，从而放心直接操作。

### 实录与深度时间

22. 作为用户，我希望实录只描述真实发生的具体日期区间，并保存来源与可选 `deep`／`shallow` 专注档位，从而不把计划冒充事实。
23. 作为用户，我希望 Agent 和手动操作都能创建、查询、修改、删除实录，并能通过原子开始／停止能力形成一段实录，从而兼顾当下记录和事后补记。
24. 作为用户，我希望开始／停止实录不自动完成 Action，完成 Action 也不伪造实录，从而保持两种事实独立。
25. 作为用户，我希望深度时间是独立的 7×24 周模板，每格可为 `high`、`medium`、`low` 或未设置，从而让 Agent 了解我的精力分布。
26. 作为用户，我希望深度时间复用当前画笔的点按和连续拖刷，同档起手清除、其他情况写入当前画笔，未设置不等于 `low`，从而快速维护且可只使用 `high`。
27. 作为用户，我希望深度时间持续复用基础周模板，并可依据实际执行与状态动态调整，从而指导后续安排；日期例外模板不在本期展开。

### 统一 Tag 与产品集成

28. 作为用户，我希望 Tag 管理只有一个入口，通过“时间／情境”切换对应标签树，从而不增加两套管理界面。
29. 作为用户，我希望所有 `kind` 共用 `id / name / kind / parentId / color` 和相同新增、重命名、删除、层级拖拽、选色操作，从而保持一致体验。
30. 作为用户，我希望一棵标签树只属于一个 `kind`，子标签继承父级类型，不能跨类型移动或建立父子关系，从而避免选择和汇总含混。
31. 作为用户，我希望关联任意层级标签时只保存实际选择项，父级查询包含直接与后代关联并按记录去重，从而兼顾粗分类和后续细化。
32. 作为用户，我希望被引用或仍有子级的标签不会被静默删除，从而保护已有事实。
33. 作为用户，我希望同名标签可以存在于不同 `kind` 中但仍是不同对象，Agent 需要消歧时使用带类型数字引用，从而无需维护额外业务 key。
34. 作为用户，我希望 Agent 与 UI 使用同一批输入输出明确的原子能力，Agent 如何使用由后续 Skill 决定，从而避免策略写死和事实分叉。
35. 作为用户，我希望产品使用 DSH 宿主主题 token，支持明暗主题与 390px 布局，并让 Agent 无独立 UI，从而与宿主自然集成。
36. 作为用户，我希望完整关闭后能从同一个 SQLite 文件恢复 GTD、日期计划、实录、模板、深度时间与 Tag，从而相信数据可持久保存。

## 实现决定

### 领域与模块

- 保留 pnpm workspace 和一个可安装 Secretary bundle，沿用现有 GTD、TimeBlock、Storage、Core 与面板装配方式。
- GTD 继续拥有 Inbox／Project／Action；Time 拥有日期计划、实录、计划模板与深度时间；新增独立 Tag 领域能力，拥有标签树及标签关联。
- 将实验面板重构为已确认的产品壳，不保留独立“时间工具”式入口或后台表单布局。
- TimeBlock 不再直接引用 Action，现有对 GTD 的创建依赖随之移除；GTD 与 Time 通过共享时间标签协作。
- Goal 不创建本期写入模型；Agent 不另建平行事实。
- 新模型使用自动生成的数字 ID。当前旧运行数据为空，不设置旧 Action／TimeBlock 兼容层或自动迁移。

### 数据契约

- `Tag`：`id`、`name`、`kind: time | context`、可选 `parentId`、可选 `color`。`kind` 由系统定义，本期不开放用户新增类型。
- `TimeBlockContent`：必填 `timeTagId` 与可选 `note`；没有 `gtdRefs`、`use` 或专用／并行分类字段。
- `PlanBlock`：`id`、带时区的 `startAt / endAt`、共享内容。
- `ActualBlock`：`id`、带时区的 `startAt / endAt`、`actualSource: user_reported | agent_observed | imported`、可选 `focus: deep | shallow`。
- 开始实录时允许存在尚未结束的运行中记录；停止时写入 `endAt`。运行中记录不得参与需要完整区间的统计。
- `PlanTemplateBlock`：`id`、`weekday`、`startTime / endTime`、共享内容。
- 深度时间：7×24 可选枚举格，值为 `high / medium / low / unset`；基础周模板持续生效。
- 标签关联只保存直接选择的 Tag。父标签查询采用直接关联加后代关联，按记录去重；GTD 有效 Tags 为自身加所有祖先，按 Tag ID 去重且不复制写入后代。
- 日期计划、实录、模板、深度时间均允许任意重叠；重叠统计口径不在本规格中定义。
- 标签引用完整性覆盖模板和日期／实录数据；存在子标签或引用时拒绝直接删除。
- 同一 SQLite 文件新增 Tag 域路由；Time 域保存时间相关事实，GTD 域保存事项事实，不引入第二套文件事实源。

### 原子能力

- GTD：保留并扩展现有 Inbox、Project、Action 查询与写入能力，输入输出显式使用领域字段和数字 ID；Availability 派生而非手工维护。
- Tag：提供 `list / get / create / update / move / delete` 及有效标签查询；输入明确 `kind`、父级和目标对象，输出包含层级、有效标签与引用错误。
- 日期计划：提供按日期 `list / get / create / update / delete`；日期与区间为必填输入。
- 实录：提供按日期或范围 `list / get / create / update / delete / start / stop`；来源、专注档位与运行中状态遵守上述不变式。
- 计划模板：提供 `list / create / update / delete / apply`；`apply` 必须显式输入模板星期、目标日期，并返回应用后的日期计划。
- 深度时间：提供读取整周、设置／清除单格或区间的能力；输入只接受封闭档位，未设置单独表示。
- UI 与 Agent 不允许绕过这些能力直接写 SQLite。

### 交互契约

- 一级产品展示 GTD、Time、Tags 和本期保留的 Goal；Agent 没有独立入口。
- Time 内部只有计划、实录、深度时间三个子模块；计划模板从计划页进入，不成为第四个子模块。
- 计划与实录复用月历、逐日导航、时间格、右侧标签架及编辑器；深度时间使用独立 7×24 周网格。
- 时间标签采用“当前画笔 + 标记态／消除态”完整矩阵：
  - 有当前标签且格内没有它：添加为并行，保留其他标签。
  - 有当前标签且格内已有它：消除该标签。
  - 双击右侧已选标签：进入消除态。
  - 消除态点击／拖刷：消除对应记录；一次拖刷只处理起手标签。
  - 单击任意标签：退出消除态。
  - Shift + 点击：打开编辑；普通点击不打开编辑器。
- 月历支持跨月与任意日期选择；日期栏和月历均提供真实“今天”。
- 时间块视觉与深度时间一致，使用宿主 token 的明暗配色，不使用卡片式粗左边条或大 KPI 区域。

## 测试决定

### 测试 seam

采用一个高层产品 seam：**真实浏览器操作和 Agent 原子工具都经过同一领域 Services，并连接真实临时 SQLite**。

- 复用现有 `packages/secretary/tests/tracer.mjs` 的 Cordis + 公共工具 + 临时 SQLite 思路，扩展 Tag、日期计划、实录、模板和深度时间。
- 在同一 seam 上运行真实客户端的 Playwright 操作，不使用静态原型代替生产 UI，也不以 scripted adapter 证明真实模型判断。
- 好测试验证用户可观察行为、公开工具输出、重新打开后的持久化和错误边界，不依赖私有函数或 DOM 实现细节。

### 必须覆盖的验收场景

1. GTD 捕获、澄清、Next Actions、日期语义、Project 类型与 Availability；两分钟立即完成事项及日常生活不进入 GTD。
2. Project 时间标签必填，所有后代累加继承，独立 Action 可直接设置；父标签查询去重。
3. 计划与实录按具体日期独立；小长假可单独编辑；计划变化不改实录。
4. 模板按星期编辑、显式应用、撤销应用、应用后互不回写。
5. 月历跨月选择、逐日前后、日期栏与月历回到真实今天。
6. 10／15／30 分钟切换不改事实；一小时一行与 48px 行高保持。
7. 完整两态矩阵、连续拖刷、同标签消除、任意标签消除、退出消除态、Shift 编辑与撤销。
8. 三条与四条并行在同一格内等分；增加或减少并行不改变小时行数。
9. 实录来源、运行中开始／停止、可选专注档位及 Action Completed 的独立性。
10. 深度时间三档、未设置、点按、拖刷、同档清除和周模板恢复。
11. Tag 的两种 `kind`、统一增改删、层级移动、防循环、防跨类型、防引用删除及画布即时更新。
12. 明暗主题、390px 无横向溢出、真实 DSH bundle 装配与新开会话生效。
13. 完整关闭并重开后，同一 SQLite 恢复全部领域事实。

原型已有的 74 项浏览器断言作为行为参考；生产验收需重新从真实客户端执行，不能直接继承原型通过结论。

## 范围之外

- Goal 的模型、UI 与实现。
- 时间预算、统计、时间对账及按 Project 汇总实录；当前 TimeBlock 不直接关联 GTD，不能假装天然支持 Project 时间归因。
- 深度时间的指定日期例外模板。
- 不同 `kind` 的差异化状态、生命周期或 OmniFocus Tag Status 对 Availability 的扩展影响。
- Agent 的调用策略、授权矩阵与具体 Skill 编排。
- 旧 JSON、Obsidian、旧 Action／TimeBlock 数据自动迁移与兼容层。
- 既有时间块拖动移动／resize、触摸端标签层级拖拽的额外验收。
- IM、云同步、多用户、完整 OmniFocus 数据导入导出与自定义 Perspective 兼容。
