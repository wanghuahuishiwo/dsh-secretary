# 产品架构

> 2026-11-02 设计中。本文记录一级模块、内部工作区与阶段边界；领域事实见 [data-model.md](data-model.md)，不在这里复制字段定义。

## 一级模块

- **GTD**：内部产品逻辑和交互复刻 OmniFocus，不重新发明核心界面。
- **Time**：管理全生活时间，内部结构由本文继续定稿。
- **Tag**：独立模块；参考 OmniFocus 的标签管理交互，并额外设计 `kind`。
- **Goal**：确认为独立且重要的一级模块，用于承载目标，并作为复盘和调整 GTD、Time 的视角；具体模型与界面挂起，本期不做。
- **Agent**：不设置独立 UI，通过现有对话与各模块中的上下文能力工作。

## Time 当前确认

### 时间计划与时间实录

- 两者是**两个子模块**，不是同一个事实或同一个列表。
- 两者都以时间轴为主要形态，复用同一套 UI、交互与**具体日期导航**；日期文字可点击打开月历并跨月选择，左右箭头用于逐日微调；日期栏和月历均提供“今天”，直接回到浏览器当前日期并高亮今天。
- 时间计划和实录都必须精确到日期；小长假等日期可直接单独设置。**计划模板是计划页中的独立功能**：按星期几维护可复用安排，可明确应用到当前日期；应用后模板与日期计划互不同步。
- 计划块首先且必须选择 `kind = time` 的时间标签，回答“这段时间准备怎么用”。**时间标签是计划块唯一的分类主体**；GTD 对象只能在备注中提及，不与计划块建立直接结构化关联，本期只实现时间标签。
- 任意时间块都可以重叠，以多个块自然表达并行活动；没有 `dedicated`（专用）类型，也没有专用块互斥限制。例如同一通勤时段可以同时记录“通勤”“听 Git 热榜视频”或“听美股大盘直播”，每块有自己的时间标签，备注可提及 GTD 对象但不形成直接关联。
- 主画布直接参照时间块 iPhone App：**一小时一行，默认每行六个独立的 10 分钟小方块**。记录跨小时时填充其覆盖的格子，标题只在首个格显示；同一格存在 N 条并行记录时，在该格内部 N 等分，三条三等分、四条四等分，**不增加小时行数，也不设并行数量上限**。
- Agent 操作与手动操作都要支持，共用原子、输入输出明确的能力；手动主交互采用与深度时间一致的“当前画笔”直接操作。
- A 方案保留右侧时间标签架，采用明确的**标记态／消除态**：单击标签进入标记态；若点击格内没有当前标签，则添加为并行并保留其他标签；若已有当前标签，则直接消除当前标签。双击右侧已选标签进入消除态，此时点击／拖刷已有记录可消除对应标签，单击任意标签退出。一次拖刷只处理起手标签，不因剩余块移动而连锁删除。普通点击不打开编辑器，Shift + 点击才编辑备注、改标签或删除。
- 时间块与深度时间使用一致的实心标签色、4px 小圆角和细间距，无卡片式粗左边条；小时行高为 48px，桌面与移动端一致。
- 时间格粒度默认 **10 分钟**，并作为可调整功能保留；粒度只影响画布显示和手动操作对齐，不是时间块的事实字段，修改粒度不重写已有记录，Agent 仍使用明确时间戳。
- 复用界面不改变事实边界：修改某日的日期计划不修改实录或计划模板，实录不从计划自动生成。

### 深度时间（精力画像）

- 在本产品中，“精力画像”和“深度时间”指向同一个精力周模板子模块，不拆成两个入口或两层模型。
- 采用 7×24 的周模板表格，每格为未设置或一个精力档位；当前档位为 `high` / `medium` / `low`，用户可只使用 `high`。
- 未设置表示没有标注，**不表示 `low`**。
- 复用 [focus-grid.html](../design/focus-grid.html) 已验证的点按、连续拖刷与取消体验；多档位采用“当前画笔”：先选 `high` / `medium` / `low`，从空白或其他档位起手时写入当前档位，从当前档位起手时清除；一次拖刷只执行同一种操作，不逐格循环，也不另设橡皮擦。
- 用途是指导用户安排，并帮助 Agent 理解用户的精力分布；不是时间实录的统计或派生视图。
- 可根据实际执行情况和当时状态动态调整；模块只提供原子、明确输入输出的完整能力，Agent 如何调用及调整策略由后续 Skill 决定，不在模块内预设工作流或权限策略。
- 一期只做持续复用的基础周模板，新一周自动沿用，不要求每周复制一份。
- 小长假等日期例外模板属于二期；一期数据结构需允许未来增加模板适用范围，不把模型锁死成“用户唯一一份不可扩展的表格”。
- 例外模板的日期粒度、冲突规则与编辑 UI 留到二期。

### 本轮不做

- 时间统计与时间对账。
- 时间预算的界面。
- 按 GTD Project、时间标签和时间周期进行统计的界面。

后续单独讨论统计专题，覆盖预算、计划与实录对账、GTD Project 维度、时间标签维度和时间周期选择。预算的入口与展示归入统计专题；预算目标是否及如何成为独立事实，留待该专题确认，不假设能从实录派生。

## Tag 当前确认

- `kind` 是系统内置的用途类型，不是用户随意创建的展示分组；它决定标签可用于哪些模块及关联校验。
- 当前仅有 `time` 和 `context`。`time` 用于时间计划／实录，也用于 GTD Project／Action 的时间分类；`context` 用于 GTD 情境分类。未来新增类型必须由产品明确其用途与规则，不能由用户随意填写新字符串。
- 每个 Project 必须设置一个时间标签，所有后代 Action 自动继承。Action 自己的 Tags 与所有 GTD 祖先的 Tags 累加，不覆盖或阻断继承；无父层级的独立 Action 需自己设置时间标签。
- 同一棵标签树只能有一个 `kind`：根标签创建时确定，子标签继承父级类型，不能跨类型建立父子关系或移动；同名标签可分别存在于不同 `kind` 的树中。
- Tag 管理只有一个入口，顶部以分段控件切换“时间 / 情境”，下方显示当前 `kind` 的独立标签树；从时间画布或 GTD 进入时自动切换到对应类型，不拆成两个一级模块。
- 所有 `kind` 共用同一套字段和管理交互；`kind` 只负责用途区分与筛选。本期不引入按类型不同的状态、专有属性或管理界面，这类细节留待后续确有需求时再讨论。
