## 4. 精力档位评估（2026-10-29）

> 2026-11-02 产品模型确认：采用 7×24 周模板，每格可设置 `high` / `medium` / `low` 或留空；留空不表示 `low`。用户可以选择只使用 `high`。

### 4.1 判定口径

- 三档：`high`（能推深度）/ `medium`（能做但连续专注打折）/ `low`（脑力打折明显）
- **档位是效率系数，不是可用性门槛**（本人 2026-10-29）：任何一档都能做同一件事，只是越往后效率越打折，用户接受这个折损。deep 的作用是**优先级信号** —— 重要任务优先占 deep，占不到就用打折时段续。
- 与 04 §1 一致：「深度和中度统一叫深度 —— 连续性比分级重要，同一项目可以上午推一段、下午接着推」
- **`deep` = `high`**；排重要任务时以它为首选
- 依据：昼夜节律两个峰 + 一个午后谷。上午峰 = 09:00–12:00，午后谷 = 14:00–16:00（post-lunch dip 由节律决定，与午餐无关），傍晚次峰 = 16:00–18:00（wake maintenance zone，睡前 1–3h 警觉性回升）
- 不采用「90 分钟专注周期」：认知表现上无证据
- 不细分到 4–5 档：主观自评与客观表现仅中等相关，档位过细信噪比差

### 4.4 结论

1. **深度时间是刚性的，几乎没有冗余。** 供给 21h20m 对需求 20h30m，余量不足 1 小时；任一次日会（3×1h/周）落到 16:00–18:00，就会挤掉深度块。
2. **深度紧不是硬顶**：14:00–16:00 的 medium 10h 可以续推同一件事，只是产出打折。真正的风险不是"时间不够"，而是**重要任务被排到只剩打折时段**。
3. **早上空档必须标 deep，否则深度池账面不成立。** 04 §1 把 07:30–09:00 的 3h30m 计入深度池，但状态曲线把它归为「上升期·轻任务」。二者只能取一 —— 按深度池口径，这段是 deep。
4. **后续统计不拍效率系数**：deep 0.9 / medium 0.6 这类数字是编的，会制造伪精确。本轮不实现统计；ActualBlock 只保存区间、直接 time Tag、来源与可选 focus。后续专题若要分析产出或 Project 归因，必须另行确认关联前提，不能凭共享 Tag 直接归属。
5. **【待校准】个体峰谷时刻可能与通用模板差 2–3 小时（chronotype）。** 跑 2–4 周真实记录后，用实测替换本表的假设时刻。
