# 小秘书 OpenDesign 效果稿 brief（PROTOTYPE）

> 目的：生成可点击、可比较的产品效果稿，回答「整体信息架构、时间块与精力属性怎样呈现最好」。这是 throwaway prototype，不是生产代码。

## 输入契约

- 产品需求以 `../../prd.md` 为准。
- 视觉参考：OpenDesign 内置 Raycast design system，只借配色、圆角、阴影、间距和字距；不要做成营销落地页。
- 宿主气质：DSH 桌面生产力工具，密集但清晰、克制、偏工作台的 `main` 整页面板。
- 最终实现会使用 DSH token 与 ui-primitives；效果稿中不要引入 shadcn 或复杂图表库作为生产依赖。

## 必做页面与交互

使用一套内存示例数据，所有视图保持一致。单页 HTML 可点击，无后端、无持久化。

### 1. 计划

- 顶部一级导航：计划 / 实际 / 对照。
- 计划页有「周时间轴 / 计划统计」两个子视图。
- 周计划每周重复，不是单日待办列表；宽屏看整周，窄屏切换星期。
- 一级/二级事项标签、可选备注、同格并行记录。
- 显示独立精力色带，可开关和切换示例精力状态。

### 2. 实际

- 有「日时间轴 / 实际统计」两个子视图。
- 时间块采用选择格子再点标签的记录方式，不用开始/结束秒表。
- 至少一个时间格有两条并行记录；至少一条有备注。
- 实际记录与计划示例数据必须有差异，不能只是复制计划。
- 精力色带与计划侧独立。

### 3. 独立统计

- 计划统计和实际统计结构完全相同，只切换数据源。
- 日/周/月切换、一级类别汇总、二级展开、总记录时长、构成比、平均值和趋势。
- 使用同一份标签色，二级是同色系稳定变体。
- 明确标注“记录时长”，不要暗示并行时长等于自然时长。

### 4. 对照

- 日双时间轴：共享时间刻度、同步滚动，左右分别为计划与实际；每侧保留并行记录和独立精力色带。
- 不跨轨连线，不做完成/延期标签，不使用 ghost overlay。
- 分类对照有「时长 / 构成比」切换：
  - 时长：Planned / Actual / Δ = Actual − Planned。
  - 构成比：计划占比 / 实际占比 / Δpp。
- 默认一级类别，可展开二级；支持按 |Δ| 排序和“仅一侧有记录”筛选。
- 必须包含仅计划、仅实际和一级直接记录（未细分）的示例。
- 可放一对细的计划/实际 100% 构成条，不要双饼图，不做复杂 BI dashboard。
- 不显示完成率，不把正负差值直接解释为好坏。

### 5. 精力属性

- 精力是独立时间格属性，不在事项标签树里。
- 示例只使用讨论过的“深度时间 / 碎片时间 / 低谷”，不要生成庞大标签体系。
- 主方案：独立精力色带，事项块保留自己的标签色。
- 精力色带清晰显示连续区间，宽屏有名称，窄屏保留色条与可访问名称。
- 计划和实际各自标注，不自动同步。

## 三个可切换变体

在同一 HTML 路由内提供浮动的变体切换条（上一版 / 当前名称 / 下一版，支持左右方向键，输入框聚焦时不拦截）。URL 使用 `?variant=A|B|C`，刷新后保留变体。切换条明确标为 PROTOTYPE。

三个变体必须包含同一组页面和示例数据，不能只换颜色：

- **A — 三视图工作台（推荐）**：顶部计划/实际/对照，时间轴为主，独立精力色带，信息层级直接。
- **B — 日期模式工作台**：以日期和周期为中枢，计划/实际作为同一时间轴的模式切换，对照时才并排；探索精力作为时间格低饱和底层 + 前景事项卡的效果。
- **C — 时间轴 + 上下文侧栏**：左侧时间轴，右侧可折叠的统计/标签/备注上下文面板；对照与复盘信息通过侧栏展开，仍保留独立精力色带。

不要只生成三个静态封面；每个变体的主要导航和交互都要能点。

## 示例数据

- 一级标签：工作、学习、生活、娱乐；二级示例：工作/写作、工作/沟通、学习/课程、生活/通勤、生活/运动、娱乐/刷手机。
- 一级选基础色，二级用同色系不同明度/饱和度，不在渲染时随机变化。
- 至少展示：通勤 + 听课程并行；实际中计划外的临时沟通；只计划未出现的阅读；只实际出现的刷手机。
- 精力区间与事项块清楚分离。
- 示例仅用于效果稿，不代表默认个人作息或固定分类。

## 视觉与验收

- 深色为默认，提供明暗主题切换以检查对比度。
- 最小检查宽度 390px；窄屏不硬压双时间轴，可切换单轨或分类对照。
- 弹层可 Esc 关闭、焦点合理、适配视口；仅图标按钮有 aria-label。
- 不使用夸张渐变、营销 hero、巨大 KPI 卡片或无意义玻璃拟态。
- 最终交付：单页 HTML、所需本地资源、简要说明；若生成 DESIGN.md，一并保留。
