# 术语表

> 小秘书领域术语的唯一入口。GTD / OmniFocus 沿用官方概念；时间系统使用小秘书自有术语；同名概念不合并。
> 数据实体与关联规则见各领域 README：[GTD](../packages/gtd/README.md)、[Tag](../packages/tag/README.md)、[时间块](../packages/time/time-block/README.md)、[持久化](../packages/storage/domain/README.md)；理论依据见 [OmniFocus 调研](research/omnifocus.md)、[GTD 理论核查](research/gtd-theory-review.md)。

## 1. GTD / OmniFocus 核心概念

| 英文 | 中文 | 定义 |
|---|---|---|
| Inbox | 收件箱 | 尚未澄清的事项暂存处，不代表已形成项目、行动或时间安排。 |
| Project | 项目 | 由一组行动共同推进的结果，描述“要达成什么”。 |
| Action | 行动 | 具体、可执行、可完成的事项。 |
| Next Action | 下一步行动 | 当前可选择的、具体可见的下一步；不等于“每个项目的第一个行动”。 |
| Action Group | 行动组 | 某个行动下的一组子行动。 |
| Folder | 文件夹 | 项目或其他文件夹的组织容器。 |
| Parallel Project | 并行项目 | 多个行动可按任意顺序完成，可同时有多个下一步行动。 |
| Sequential Project | 顺序项目 | 后续行动受前序行动阻挡。 |
| Single Actions List | 单一行动清单 | 不共同服务一个结果的独立行动集合。 |
| Waiting For | 等待 | 下一步由别人或外部条件推进的事项。 |
| Someday / Maybe | 将来也许 | 暂不承诺，但保留以后考虑的事项。 |
| Context | 情境 | 地点、工具、人员等执行条件，用于选择当前适合做什么。 |
| Tag | 标签 | 共享 Tag 模块中的分类对象；GTD 可使用 `time` 与 `context`，TimeBlock 只使用 `time`，不改变 Project 归属。 |
| 有效 Tags | 有效标签 | 对象自己的 Tags 与所有 GTD 祖先 Tags 的累加结果，按 Tag id 去重；自己设置不会覆盖或阻断继承。 |

## 2. 日期、状态与可用性

| 英文 | 中文 | 定义 |
|---|---|---|
| Defer Date | 推迟日期 | 不早于此时间开始可用；不是计划执行时间。 |
| Planned Date | 计划日期 | 打算何时开始做，是柔性意图；是时间点，不是时间区间。 |
| Due Date | 截止日期 | 必须在此前完成或放弃的外部约束。 |
| Estimated Duration | 预计时长 | 对所需工作量的估计，不是计划区间或实际时长。 |
| Status | 状态 | Active、Completed、Dropped 等直接状态。 |
| Availability | 可用性 | 由状态、Defer、项目类型等派生的可否执行判断，不手工维护。 |
| Available | 可做 | 当前可以承接。 |
| Blocked | 被阻挡 | 行动仍有效，但被 Defer 或前序条件暂时阻挡。 |
| Unavailable | 不可做 | 行动或其所属上下文已不再处于可执行状态。 |
| First Available | 首个可用 | 当前排序下第一个可用行动，不表示 GTD 中只能有一个 Next Action。 |
| Completed Date | 完成时间 | 行动变为 Completed 的时刻，不是实际工作区间。 |
| Dropped Date | 放弃时间 | 行动变为 Dropped 的时刻；放弃不等于完成。 |

## 3. 视图与工作流

| 英文 | 中文 | 定义 |
|---|---|---|
| Perspective | 视图 | 查看同一批事实的一种方式，不是新实体或另一份数据。 |
| Forecast | 日期视图 | 按日期查看 Planned、Due 等内容。 |
| Today | 今天视图 | 日期视图中的派生筛选，不是独立行动清单或实体。 |
| Review | 项目检视 | 检查项目状态、下一步和组织结构；不同于时间对账。 |
| Repeat | 重复 | 按规则产生下一次行动或项目。 |

## 4. 小秘书的时间系统

| 术语 | 定义 |
|---|---|
| 时间计划 | 某个具体日期的时段安排，与实录使用相同的日期精度；小长假可单独设置，不要求关联 GTD。 |
| 计划块 | 具体日期计划中的一段区间，必须且只以时间标签作为分类主体；GTD 对象只能在备注中提及，不建立直接结构化关联。 |
| 计划模板 | 计划页中独立维护的可复用星期模板；可明确应用到指定日期，应用后不与日期计划自动同步。 |
| 时间实录 | 实际发生的时间分布，不从时间计划自动复制。 |
| 实录块 | 具体日期中的一段实际时间，必须且只以时间标签作为分类主体；备注可提及 GTD 对象，但不形成直接关联，也不自动完成行动。 |
| 时间预算 | 各类时间的总量分配目标，例如每周睡眠 52h、技术 12h；不指定具体时段。 |
| 时间对账 | 比较时间计划、时间实录和时间预算，发现偏差、时间黑洞与杠杆机会。 |
| 时间类别 | `kind = time` 的时间标签，用于时间计划、实录与统计，如睡眠、工作、技术、娱乐。 |
| Tag Kind | 系统内置的标签用途类型，决定标签语义和允许的关联对象；当前只有 `time` 和 `context`，不是用户随意创建的分组。同一棵标签树只能有一个 `kind`，子标签继承父级类型。 |
| 深度时间（精力画像） | 指导用户安排并帮助 Agent 理解精力分布的周模板；本产品中“精力画像”与“深度时间”指同一子模块，不是时间实录的派生统计。采用 7×24 表格，每格可为 `high` / `medium` / `low` 或未设置；未设置不等于 `low`，用户可只使用 `high`。 |
| 专注档位 | 实录块所反映的实际专注状态，不是行动状态或时间类别，也不自动改写深度时间周模板。 |
| 并行时间 | 任意计划块或实录块都可以重叠，以多个块表达同一时段的多项活动；没有 `dedicated`（专用）类型、互斥限制或额外并行标记。 |
| 实际来源 | 实录依据来自用户陈述、Agent 观察或外部导入，保留事实的可信边界。 |
| TimeBlock | 界面与技术组件名；业务概念分别使用“计划块”和“实录块”，不把计划与实际混成一种事实。 |
| 时间格粒度 | 时间画布显示及手动点选、拖选的对齐步长；固定 10 分钟一格（用户习惯的粒度），不是 TimeBlock 的事实字段。数据层仍接受任意分钟的时刻，画布按整格外扩显示，不改写存储。 |

## 5. 秘书与宿主

| 术语 | 定义 |
|---|---|
| Agent | 以同一个秘书身份承接、协商、准备和跟进，操作同一批事实，不另建数据。 |
| Proposal | 秘书提出但用户尚未认可的方案，不是已确认安排或已发生事实。 |
| Preparation | 为后续行动提前准备的清单、摘要、议程或初稿，不等于行动已执行或完成。 |
| DSH Schedule | 宿主的定时唤醒能力，只负责投递提示，不是时间计划、Repeat、实际执行或完成回执。 |
| Service | 插件暴露给其他插件的 Cordis capability。 |
| Projection | 从权威事实即时派生的读取结果，如 Availability、Forecast 和各种视图，不另存事实。 |

## 6. 必须保持的边界

1. **Planned Date ≠ 时间计划**：前者是行动的时间点属性，后者由多个时间区间组成。
2. **Completed ≠ 时间实录**：完成回答“事是否做完”，实录回答“时间实际怎么花的”。
3. **项目检视 ≠ 时间对账**：前者维护承诺，后者分析时间。
4. **Tag Kind 不可混用**：`time` 可用于 TimeBlock 和 GTD 的时间分类，`context` 用于 GTD 情境；TimeBlock 只能使用 `time`，同一棵树不混用类型。
5. **Perspective ≠ 新事实**：Today、Next、Forecast 和统计都应读取同一事实源。
