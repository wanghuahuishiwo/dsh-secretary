- 调研日期：2026-10-26（Asia/Shanghai）
- 调研对象：App Store ID `1086617993`，Bundle ID `com.anniapp.Timeblocks`，开发者/销售方「妮 安」的《时间块 - 快速记录时间规划日程安排》。[S1] [S2]

## 3. 一页概念模型总结

### 3.1 官方概念列表

| 官方用词 | 在产品中的角色 | 证据与边界 |
|---|---|---|
| **时间块 / 块** | 被划分和被标记的时间单位 | 开发者明确说将连续时间分成一块块，以 30 分钟或手动开启的 15 分钟为最小单位。[S1] [S2] |
| **事件** | 被记录、分类和分析的“事情” | 开发者使用“记录每件事所花费的时间”“事件分类”“事件和对象关联”等表述。资料没有暴露名为 Event 的独立实例结构。[S1] [S2] |
| **事件类别 / 类别** | 事件的第一层分类，也是记录时可选的标签 | 官方截图的列表和统计页使用“事件类别”；Apple 编辑说明称事件按“类别－内容”组织。[S4] [P2] [P5] |
| **内容** | 类别下的具体内容，可作为更细的标记与追踪单位 | Apple 编辑示例：“工作”类别下有“开会”“写作”“整理资料”等内容；一段时间可标记为类别或内容。[S4] |
| **对象 / 关联对象** | 与事件关联、可从另一视角统计的第二维度 | 开发者示例：“上课”“考试”都可关联“语文”“数学”；统计截图可见“关联对象”视角。[S1] [S2] [P2] |
| **备注** | 某段时间的详情 | 开发者与 Apple 编辑均明确说明可给事情/每段时间添加备注。[S1] [S4] |
| **目标** | 对累计投入时长及进度进行追踪的目标 | 开发者示例为“在 5 年内画画达到 10000 小时”；截图显示进度、已投入/目标小时数和进行天数。[S1] [P4] |
| **时间记录 / 记录** | 记录行为及其结果的通用称呼 | 官方没有把“记录”定义成可供用户管理的独立对象类型，不能据此假定其存储结构。[S1] [S3] |
| **时间轴 / 时间表** | 查看和编辑已标记时间的界面/导出结果 | 当前更新说明使用“时间轴”；开发者描述与快照截图使用“时间表”。[S1] [S2] [P6] |
| **统计 / 趋势** | 对已记录时间进行分析的两个视图 | “统计”偏占用比、平均值、饼图/柱图；“趋势”偏多事件折线对比。[S1] [S2] [P2] [P3] |
| **快照** | 将某天时间表保存到相册或分享的输出 | 官方截图的明确名称和用途。[P6] |

**术语警戒：**“内容”和“对象/关联对象”很可能指向同一个第二分析维度，但官方资料没有给出术语对照表；本报告只把它们并列呈现，不把二者相等写成事实。“事件”与“事件类别”也存在语境交叠，不能擅自对应到某种任务数据库实体。

### 3.2 关系与主闭环

```text
【官方明确：Apple 编辑】
事件按“类别－内容”组织
例：工作 ── 开会 / 写作 / 整理资料

【官方明确：开发者】
事件“上课、考试” ── 都可以关联 ── 对象“语文、数学”
                 因而能从事件或对象两个视角分析

【官方明确：Apple 编辑 + 当前更新说明】
一段时间 / 所选块 ── 用事件标签标记为类别或内容
每段时间 ── 可附备注
已标记时间 ── 进入统计与趋势

【官方明确，但关联规则不完整】
目标 ── 展示累计时长、进度和每天还需投入量
```

上述关系的来源分别为 [S4]、[S1]、[S2]、[S3]、[P4]。其中“内容＝对象”只是可能的术语归并，未画成既定等式。

**【推断】**最小产品闭环不是“创建任务 → 开始计时 → 完成任务”，而是：

1. 先定义可复用的事件类别，必要时补充内容/对象；
2. 在事后或闲暇时选择时间块，用类别或内容标记，并可写备注；
3. 同一类别或内容可反复用于不同日期的多个块；
4. 按所选时间范围，从类别或对象视角汇总已记录时间，再查看统计或趋势。[S1] [S3] [S4]

### 3.3 可安全借鉴的最小模型【推断/设计建议，非官方字段】

若只借鉴已由官方材料支持的最小闭环，可以先保留：

- **事件类别**：名称、颜色；颜色用于在时间轴上快速辨认记录。[S3] [S4] [P1]
- **时间区间记录**：开始时间、时长、一个主要类别、可选备注；区间对齐 15/30 分钟网格。这里用“区间记录”统一表达官方的一块或一段多块，不声称这是官方存储结构。
- **派生统计**：按日/周/月所选范围，对区间时长按类别求和。先做总时长，不猜官方“平均值”和“占用比”的分母。[P2]
- **可选的特色扩展**：加入第二维度“内容/对象”及其与类别的关联，再支持双视角统计；这是该产品区别于单一标签模型的关键。[S1] [S4]

第一刀不必引入“任务”“计划与实际双记录”，也不必先实现目标、趋势、快照。目标虽为官方功能，但它与事件/内容的精确关联字段尚未查明；统计比例与平均值也应先确定自己的产品口径，而不是冒称复刻官方算法。

## 4. 核心对象与对象关系：详细证据

### 4.1 块是时间单位，不是已证实的“任务实例”

- **【官方明确】**开发者解释“时间块”名称：虽然时间连续，为了节约记录成本，主动牺牲精度，把时间分成一块块，再“一选一点”记录。最小单位为 30 分钟或设置中手动开启的 15 分钟。[S1] [S2]
- **【官方明确】**它不用传统的“开始/结束”计时；用户可在闲暇时补记一整天的事情。[S1]
- **【官方明确】**Apple 编辑描述：左侧一个方块代表半个小时，选择时间后点击右侧事件标签，方块即被标上相应颜色。[S3]
- **【推断】**因此，块首先是时间网格中的可标记单元；已查资料不支持把“块属于某类任务”当成官方模型。官方使用的是事件、类别、内容、对象，而不是任务。

**仍未知：**官方没有说明一个块能否同时关联多个类别/内容，也没有公开底层记录表；不能从单色界面反推出硬性的数据库单值约束。

### 4.2 事件类别与内容

- **【官方明确】**开发者称事件分类完全自定义，可按大类（工作、娱乐）、具体内容（玩手机、看电视）或轻重缓急（紧急、重要、不重要）分类。[S1] [S2]
- **【官方明确】**Apple 编辑进一步给出结构：“事件按照‘类别－内容’来组织”；“工作”是类别，“开会”“写作”“整理资料”是其下内容。用户可以把一段时间标记为“类别”或“内容”。[S4]
- **【截图可见】**“事件类别”管理页以缩进列表展示类别及其下内容，例如“看电影－盗墓笔记”“运动－足球”；页面可见新增与编辑入口图标。[P5]
- **【未知】**截图中的加号、编辑图标没有配套帮助说明，无法还原创建类别、创建内容、排序、删除和改名的完整交互；也未证实除“类别－内容”外还能有多少层级。

### 4.3 事件与对象/关联对象

- **【官方明确】**开发者的关键例子是：“上课”和“考试”两个事件都可以关联“语文”和“数学”两个对象；既能从事件角度分析包含语文、数学的“上课”用时，也能从对象角度分析属于上课、考试的“语文”用时。[S1] [S2]
- **【官方明确】**这不是只能沿单一路径汇总的树：至少在该例子中，多个事件可共同关联多个对象，官方明确支持事件与对象两个分析方向。[S1] [S2]
- **【截图可见】**统计页可辨认“事件类别”和“关联对象”两个视角；类别管理截图也会在不同类别下重复出现相同内容名称。[P2] [P5]
- **【推断】**把第二维度理解成可复用、可跨事件关联的对象，比把它理解成每类别下互不相通的私有子类更贴近开发者示例。不过，截图里重名内容是否为同一底层对象，官方没有展示。
- **【未知】**“类别－内容”和“事件－对象”是否是同一模型的两套措辞，官方未直接说明；本报告保留这一术语缝隙。

### 4.4 备注、目标与输出物

- **备注【官方明确】**：每段时间都可添加备注；示例是用备注记录“与市场部同事讨论广告物料”这类比类别/内容更具体的详情。[S1] [S4]
- **目标【官方明确】**：可设长期累计时长目标，例如五年画画 10000 小时。[S1]
- **目标【截图可见】**：目标列表显示名称、百分比进度、已投入/目标小时数、已进行天数；截图文案称会告诉用户接下来每天要做多少才能达成。[P4]
- **目标【未知】**：资料没有完整说明目标可绑定类别、内容、对象还是其组合，也没有说明期限、开始日期、暂停和超期的全部规则。
- **快照【截图可见】**：记录的时间表可保存到相册或分享，导出图上呈现日期和“我做的事情”。[P6]

| 记录详情 | **【官方明确】**每段时间可加备注。[S1] [S4] | 备注是每块一条还是随多块区间共享，官方未说明。 |
| 设目标 | **【官方明确】**可设累计小时目标。[S1] **【截图可见】**目标列表有新增入口。[P4] | 完整创建表单及绑定规则未知。 |

### 5.2 “同一任务如何跨多个块”的准确回答

1. **【推断】**所查官方资料没有定义“任务”这一核心对象；与用户所问“任务”最接近的是可复用的事件类别或更具体的内容/对象。[S1] [S4]
2. **【官方明确】**记录时会把所选时间块标上所选事件标签；当前版本说明又明确存在多选块操作。[S2] [S3] **【推断】**要表达同一件事跨多个块，就是复用同一类别或内容进行标记，并可跨日期反复记录，而不是必须先创建一个任务再挂接块。
3. **【官方明确】**另一种“跨”是分析维度上的跨事件：同一“语文”对象可关联“上课”和“考试”，再汇总该对象的用时。[S1]
4. **【未知】**选择连续多个块后，是形成一条长区间记录、多个共享标签的块记录，还是仅属 UI 多选，官方没有公开。设计参考时可以自主选择区间或块存储，但不能称为官方实现。

## 6. 是否有“计划”与“实际”之分

- **【官方明确】**现有核心描述把产品定位为记录实际时间“开销”的工具：记录每件事花费的时间、回顾时间去向，并据此统计。[S1] [S3] [S4]
- **【官方明确】**“目标”用于设立累计投入时长并追踪进度。[S1] [P4] **【推断】**它不应被等同于逐块排好的计划日程。
- **【未知】**App 标题虽含“规划日程安排”，当前更新说明虽含“对照模式”，但所查描述没有解释计划对象、计划块、实际块、完成状态或二者对照规则。“对照模式”具体比较什么也未知。[S1] [S2]
- **结论边界：**应写成“官方资料未证实计划/实际双模型”，而不是绝对声称 App 没有相关功能。更不能因为标题含“规划”就补出 planned/actual 两套时间字段。

## 7. 日 / 周 / 月统计的口径

### 7.1 官方明确与截图可观察的部分

| 方面 | 结论 | 证据等级与来源 |
|---|---|---|
| 时间范围 | 可按**天、周、月、季、年、指定时间段**查看统计 | **【截图可见】**统计截图顶部文案原文如此。[P2] |
| 指标名称 | 可查看**时间占用比和平均值** | **【截图可见】**同一统计截图文案。[P2] |
| 图形 | 以饼图、柱图等多种方式分析时间占用比 | **【官方明确】**开发者功能描述；截图可见横向条形和环形图。[S1] [P2] |
| 分类视角 | 可从事件和对象两个方向分析；统计页可见“事件类别 / 关联对象” | **【官方明确 + 截图可见】**[S1] [S2] [P2] |
| 趋势 | 可对比多个事件逐日、逐月用时 | **【官方明确】**开发者描述。[S1] [S2] |
| 趋势视图 | 截图中可见“周视图 / 月视图 / 年视图”和多系列折线 | **【截图可见】**[P3] |
| 块精度与长期统计的关系 | 开发者认为块化的小误差在周、月跨度上对分析影响很小 | **【官方明确】**这是开发者的产品取舍说明，不是统计算法。[S1] [S2] |

### 7.2 可作出的保守解释【推断】

已标记的块是统计输入，类别/内容是分组维度，日/周/月等是时间范围；统计页做占用比和平均值，趋势页做多事件时间序列对比。这个解释同时符合记录流程、开发者功能描述和截图。[S1] [S3] [S4] [P2] [P3]

“每块时长 = 15 或 30 分钟，汇总已标记块得到事件用时”是自然的实现推断，但官方没有公开计算公式或数据导出规范，因此不把它写成已验证算法。

### 7.3 明确未知的统计规则

以下问题均未由官方资料回答，不能用二手文章补齐：

1. “平均值”是除以自然日、已记录日、周数、月数，还是其他分母？
2. “占用比”的分母是全部已记录时间、所选范围的全部自然时间，还是含未标记时间的其他口径？
3. 周从周一还是周日开始；日边界、时区和跨午夜记录如何处理？
4. 当前未结束的日/周/月是否按完整周期还是截至当前计算？
5. 类别与内容/对象同时存在时，各视角如何避免重复计数？
6. 未标记时间是否形成独立分组，是否进入平均值和占用比？
7. 趋势中“逐日/逐月”与“周/月/年视图”如何组合，缺失日期是否补零？

因此，参考其模型时可以安全借鉴“按范围 + 分类汇总时长”，不能直接复制一个自称与官方一致的百分比或平均值公式。

## 8. UI 主视图结构

### 8.1 时间轴主视图

- **【官方明确】**Apple 编辑将主操作描述为左侧时间块、右侧事件标签；点击左上角菜单可进入“统计”。[S3]
- **【截图可见】**主画面中央/左侧是带小时刻度的纵向时间网格，日期沿时间轴排列；不同事件以不同颜色填充块。右侧是“上班、阅读、运动”等事件类别按钮及“更多事件类别”。[P1] [P8]
- **【截图可见】**顶部可见菜单和日期/导航相关控件；底部可见详情区域，例如“看电视－西游记”及一行详情文字。[P1]
- **【官方明确】**当前更新说明仍以“时间轴”称呼标记、擦除和多选所在界面，并新增可缩窄的“对照模式”；底栏可显示选中内容块的时长。[S2]
- **【未知】**“对照模式”的比较对象、当前版本的全部导航项，以及截图中的旧控件是否原样保留，均不能从现有资料确定。

### 8.2 其他主要视图

- **事件类别页【截图可见】**：类别与缩进内容组成的列表，用于管理分类。[P5]
- **统计页【截图可见】**：时间范围/日期控制、事件类别或关联对象视角、条形图和环形图。[P2]
- **趋势页【截图可见】**：周/月/年视图切换与多事件折线。[P3]
- **目标页【截图可见】**：目标列表、新增入口、百分比环和进度文案。[P4]
- **快照输出【截图可见】**：将某日时间表生成可保存/分享的图像。[P6]

**【推断】**信息架构的中心是“时间轴记录”，分类管理是记录准备，统计/趋势/目标是基于记录的分析与追踪，快照是输出。所查截图没有支持把底部 Tab 任务列表或日历周计划当作主视图。
